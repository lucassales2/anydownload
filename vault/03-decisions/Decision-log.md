# Decision log

[Home](../Home.md) · [Architecture](../02-architecture/Architecture.md) · [Open questions](../00-project/Open-questions.md)

**ADR-004 is accepted** as the end state. **ADR-005 is accepted** as Phase D1 (done): desktop Compose UI via installed yt-dlp. **ADR-006 is accepted** as Phase D2 (done): shared HTTP-only engine on all four hosts, web via extension, Android Chaquopy interim. **ADR-007 is accepted** as Phase D3 (done): one generic-extractor subset on all four hosts; the media toolkit is recorded and not built. **ADR-008 is accepted** as Phase D4 and **done 2026-09-24** (verified by T-074): extractor core plus YouTube single video on all four hosts, JS-less first and then yt-dlp-ejs on an embedded runtime; equivalence with yt-dlp is measured in the [equivalence note](../01-product/Ytdlp-equivalence.md). **ADR-009 is accepted** as Phase D5 and **done 2026-09-25** (verified by T-083): the media toolkit merges one video stream with one audio stream and copies or converts audio on desktop, Android, and iOS; web stays a documented gap. **ADR-010 is accepted** as Phase D6 and **done 2026-09-25** (verified by T-093): spotDL v4.5.2 parity on the shared engine, with the four-host result and the mobile/web gaps recorded. **ADR-011 is accepted** as Phase D7 and **done 2026-09-25** (verified by T-100): the public X/Twitter status video on all four hosts, with the opt-in live status and the web end-to-end gaps recorded. Earlier remote-server proposals are superseded. ADR-002 is still a proposal: YtDlp-kt remains a JVM CLI wrapper, not the Kotlin port.

The project license is MIT as of 2026-09-21. A 2026-09-23 comparison of Python packagers and the Kotlin port is in [Client yt-dlp options](../05-research/Client-yt-dlp-options.md). It does not replace ADR-004. Owner answers the same day: Unlicense yt-dlp may be translated with notices; MeTube/NewPipe/YtDlp-kt must not be copied; Q-09 is allowlist. The per-target media toolkit and the first extractor are recorded in [ADR-007](ADR-007-Generic-extractor-phase.md). Owner answers on 2026-09-24 ([ADR-008](ADR-008-Extractor-core-and-youtube-phase.md)): the end goal is yt-dlp feature equivalence (core engine plus the catalog over time); D4 is the extractor core and YouTube single video staged JS-less then EJS; the toolkit stays unbuilt; yt-dlp-ejs 0.8.0 is bundled and hash-verified; the pin stays `2026.08.19`; the format-spec language is ported; the CLI and Chaquopy become an opt-in oracle; X/Twitter is the next named site. Owner, 2026-09-25 ([ADR-009](ADR-009-Media-toolkit-phase.md)): the phase after D4 is the toolkit build. Later the same day ([ADR-010](ADR-010-Spotdl-parity-phase.md)): the phase after the toolkit is spotDL parity, and X/Twitter follows that. D7 then ported the public X/Twitter status video ([ADR-011](ADR-011-X-twitter-phase.md)): public guest lookup only, no cookies, no vendored `twitter.py`, no `yt-dlp` process for a matched status URL, and no live mobile/web X run. The pin was rechecked that day and is still `2026.08.19`. Use the [ADR template](../99-templates/ADR-template.md).
