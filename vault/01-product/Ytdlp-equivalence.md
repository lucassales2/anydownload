# yt-dlp equivalence matrix

**Baseline:** yt-dlp tag `2026.08.19`, commit `3a08beaf031ab68f966401ead017ac81fe8486cf`, inspected 2026-09-24. This note is the target for "the Kotlin port of yt-dlp" from [ADR-004](../03-decisions/ADR-004-Local-kotlin-engine.md). The [MeTube matrix](Feature-parity.md) covers the product workflows on top; this one covers the engine underneath.

Two halves, decided by the owner on 2026-09-24 ([ADR-008](../03-decisions/ADR-008-Extractor-core-and-youtube-phase.md)):

1. **Core engine** — the hand-written table below. A row is *Done* only when the owning task links tests on every host the row applies to.
2. **Extractor catalog** — 1,751 extractor classes named in upstream `_extractors.py` at the pin. Coverage is a generated table from `port/manifest.json` ([T-055](../06-tasks/T-055-Port-manifest-and-equivalence-matrix.md)). Nobody edits that table by hand.

Statuses: **Done** (tested on every applicable host), **Partial** (subset shipped; the note says which), **D7** (in the current phase), **Later** (planned, no phase), **Out** (deliberately not equivalent; the reason is in the row).

## Extractor coverage

Machine-readable record: `port/manifest.json` lists every translated module with its upstream path, tag, commit, status, scope, and Kotlin files. `port/upstream-extractors.json` is the sorted class-name list read from upstream `_extractors.py` at the same pin (data only, no upstream source). Regenerate the block below with `./gradlew :tools:port-manifest:run`; validate the manifest and the block in CI with `./gradlew :tools:port-manifest:check`. Do not edit the block between the markers by hand.

Counting rule: an extractor is **Ported** when its `_real_extract` behavior for the URL forms listed in the manifest is translated and its harness cases pass; **Partial** when a named subset is translated (the manifest names it); **Planned** when a task exists; otherwise **Not started**. A count is never rounded up.

A task that ports a module updates `port/manifest.json` in the same change and reruns the generator; the coverage counts and the module table below follow from that file alone. The first generation seeded the D3 generic subset as partial ([T-045](../06-tasks/T-045-Generic-extractor-subset.md)), the YouTube single video as planned ([T-060](../06-tasks/T-060-Youtube-jsless-extractor.md)), and D7 added `TwitterIE` partial ([T-094](../06-tasks/T-094-Twitter-status-extractor.md)).

## Differential oracle (E-28)

The desktop differential compares the Kotlin extractor with the installed upstream tool on the same public URL. It runs only when explicitly enabled and never in default CI:

```sh
./gradlew :apps:desktop:test --tests "com.anydownlod.desktop.engine.YtDlpOracleTest" -PytDlpOracle=true
```

- Preconditions: `yt-dlp` on `PATH` at the pin `2026.08.19`. Without the property, or with any other version, the test is skipped and reports the version it found. The executable is started with an argument list, never a shell string; `ProcessBuilder` stays under `apps/desktop`. The oracle runs `yt-dlp -J --no-warnings --extractor-args "youtube:player_client=visionos" <url>` so both sides use the same innertube client.
- Compared fields: `id`, `title`, `channel_id`, `upload_date`, `age_limit`, `duration` (±1s), and the format set keyed by `format_id` with `ext`, `vcodec`, `acodec` (a missing codec equals `none`), `height`, `fps` (±0.001), and `protocol`. Ignored: URLs, `filesize`, `view_count`, thumbnails, and storyboard-only rows. The raw `-J` document contains signed media URLs, so it is parsed and discarded, never printed or stored.
- A divergence is a failure whose message lists field names and normalized values only; a `googlevideo` host in the diff fails the test explicitly.
- Allowed inputs live in `YtDlpOracleTest`: the public Big Buck Bunny URL plus its audio-only formats. Add cases there, not to CI.
- First run (2026-09-24) found real gaps in the T-060 translation: `isDrc`/`xtags` format-id suffixes (`-drc`, `-sr`) and the watch-page `uploadDate`/`familyFriendly` fallbacks. After fixing them the differential reports `27/27` formats and `0` diffs.

## How to use this matrix

1. Keep E-IDs stable. Add rows when upstream gains a capability the port must answer; mark rows Out with a reason rather than deleting them.
2. A task that ports a module updates `port/manifest.json` in the same change and regenerates the coverage block.
3. Statuses change only with linked evidence in the owning task. "Compiles" is not evidence; a harness or host test is.
4. The pin moves only at a phase boundary and is recorded in the ADR for that phase, the manifest, and every notice header the change touches.
